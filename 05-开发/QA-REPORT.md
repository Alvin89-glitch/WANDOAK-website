## 4 · Technical artist 阶段修掉的问题

按发现顺序，全部有实测或截图证据。

### 严重

**1 · Hero 文字被自己的蒙版盖住。**
`.hero::after` 的渐变蒙版和 `.hero__inner` 在同一个层叠上下文里，伪元素在源码顺序上更靠后，
所以蒙版画在了文字上面。白色 60px 标题实测对比度约 **2:1**，按钮看起来是灰的。
修法：`.hero__inner { z-index: 2 }` / `::after { z-index: 1 }`，并按实际天空亮度加重了渐变。
现在最差一处（hero h1 压最亮的 10% 天空）是 **6.50:1**。新增断言 `A16` 盯着这件事——
它是把文字藏起来、只拍文字底下的像素来测的，直接测文字会量到白对白。

**2 · 移动端 Hero 标题被截掉。**
390px 下 caption 比 1:1 的图还高，`align-items: flex-end` 让它向上溢出，第一行钻到 sticky 导航底下。
修法：≤767px 改为图在上、文字在下的堆叠版式，蒙版取消，文字直接压黑底。新增断言 `A18`。

**3 · CLS 0.507。**
首页路由是动态 import，首屏 `<main>` 是空的，页脚直接顶到导航底下；chunk 到了之后页脚整屏下移。
修法：首页路由改为静态导入（它是落地页，拆包只换来一次往返），并给 `main` 加
`min-height: calc(100svh - var(--nav-h))` 兜住所有懒加载路由。**CLS 0.507 → 0。**

**4 · 中文站白下载 1.35 MB 字体。**
`@fontsource/noto-sans-sc` 按 unicode-range 切成上百片，中文页面会拉走其中约 40 片 × 3 字重。
修法：构建期向 Google Fonts 要**只含本站 865 个字**的子集并落到本地。**1350 KB → 383 KB**，运行时不依赖 CDN。
第一版脚本还踩了个坑：`text=` 参数在 URL 过长时会被**静默忽略**、退回完整字体（13 MB）。
脚本现在分批请求，并在返回超过一个 `@font-face` 时直接报错。

### 几何（对着 alo-spec 实测值）

| 问题 | 实测 | 修法 |
|---|---|---|
| 导航高 84.5px，应为 83.5 | 1px 描边加在了 sticky 外层 | 描边移进 `.nav__bar` 内侧——ALO 本来就是 82.5px 行 + 1px 线 |
| Hero 高 557.25px，应为 575.25 | 用了图片自身的 1920/743 比例 | 版面要复刻的是**盒子**比例 1440/575.25；照片是 object-fit cover 进去的 |
| 区块间距 70/86/54 混杂 | 是 harness 的问题：入场动画的 16px 位移还没走完就量了 | harness 改成像人一样逐屏滚动（IntersectionObserver 会跳过一次跳到底的元素），并等位移归零 |

# 附录 · Phase 2：产品页与工厂页（2026-08-20）

`npm run qa` 现在跑 **24 项断言，全绿**。新增 4 项，其中 3 项是在开发过程中抓到真实缺陷后补上的。

## 1 · 新增断言

| # | 断言 | 为什么加 |
|---|---|---|
| `A19` | products + factory 保持 70px 节奏、1350 容器、七档字号、图片完整性 | 新页面引入了 5 宫格与 4 宫格车间条，是最容易把栅格撑破的地方 |

| `A21` | 瞬间跳到页面底部后，入场动效仍然显形 | **抓到真 bug**，见下 |
| `A22` | 内页 hero 恒为 1300×445.9，320–1440 全程不裁标题 | **抓到真 bug**，见下 |

## 2 · 本轮修掉的缺陷

### 严重

**1 · 内页 hero 的标题在窄视口被整段裁掉。**
`.ih__frame` 的高度只由图片的 2.9155:1 比例决定，`.ih__overlay` 是绝对定位的，撑不开父容器，超出部分被 `overflow: hidden` 吃掉。实测：

| 视口 | /factory | /products | /partner |
|---|---|---|---|
| 390px | 裁 201px | 裁 156px | 裁 243px |
| 768px | — | — | 裁 28px |
| 1024px | — | — | 裁 20px |

**合作页是上一轮就标为"已完整实现"的页面**，它在三档宽度下都在裁自己的标题，此前无人发现。
修法：`.ih__frame` 改为 grid 同格堆叠，行高取图片与文字块的较大者。断言 `A22`。

**2 · 内页 hero 的几何跟着素材走。**
`/design` 传了一张 editorial 比例（1.111:1）的图，页头被撑成 **1170px**，是规格值 445.9px 的 2.6 倍。
修法：`InnerHero` 自己持有 Container C 几何，`aspect-ratio: 1300 / 445.9 !important` 覆盖 AppPicture 写在行内的素材比例。同样由 `A22` 盯着。

**3 · 瞬间跳到页面底部会让中间区块永久不可见。**
`.reveal` 靠 IntersectionObserver 显形。IO 只在相交比例跨过阈值时回调；浏览器恢复滚动位置、锚点跳转、按 End 键都会让中间区块在两帧之间从"屏幕下方"变成"屏幕上方"，一次都没相交，于是永远停在 `opacity: 0`。工厂页实测 7 个区块里有 4 个卡住。
`verify.mjs` 的 `settle()` 一直是逐步滚动的（注释里也写了"a single jump can skip whole sections"），所以这个问题在测试侧被绕过、在生产侧没被发现。
修法：`useReveal` 加一个共享的、rAF 节流的滚动兜底，把已经滚过头的元素放出来，最后一个元素显形后自行注销监听。断言 `A21`。

### 中等

**4 · 内页 hero 叠字对比度不足。**
`InnerHero` 用的是自下而上的竖向渐变，而标题位于文字块上半部、正好落在遮罩最淡处。实测工厂页标题 **3.05:1**、产品页 **4.27:1**，均低于 4.5 门槛。
修法：改用与首页 Hero 一致的横向为主渐变（文字在左下角，横向 ramp 才是起作用的那个）+ 竖向补足，文字块 800→720px。修后 10.68:1 / 10.25:1。断言 `A20`。

**5 · `document.title` 含换行。**
`factory.heroH1` 的中文版带 `\n`（排版用），直接进了 `<title>`。`syncHead()` 现在折叠空白。

**6 · 五张单品图人物比例不一致。**
实测人物高度占各自画幅的 0.782–0.843，并排时最小的那张明显小一圈、位置偏高。按最大占比 0.843 归一化裁切窗口，并对齐各自的人物包围盒中心。

**7 · 图片管线的 `top` 参数被误用。**
`top` 是**区域上沿**且 `height` 默认取 `1 - top`，所以 `top: 0.5` 会把可用区域砍成下半幅、再从中取一个远小于画面的窗口。对 `cta` 那种极宽比例无害（现有的 `cta-floor` 就这么写），但对 `editorial` / `floor` 比例会裁出一小块无意义的画面——`fac-setting` 一度裁成一块空白金属板。9 处已修正。

**8 · `npm run qa` 永不退出。**
旧脚本用 `&` 起 preview 又没人回收，命令挂住；残留进程还会顶掉下一次的 `--strictPort`，导致断言悄悄打在旧构建上。改为 `scripts/qa.mjs`：起服务 → 轮询就绪 → 跑断言 → 收尾。实测 79 秒跑完并自行退出。

### 事实性修正

**9 · `fac-setting`（原 `fac-spread`）的说明文字写错了。**
机器铭牌是 "NFD-1 数控定型机"，是热定型机不是铺布机。alt 文案已按铭牌改正。

# 附录 · Phase 3：产品页的第二层级（2026-08-20）

`npm run qa` 现在跑 **26 项断言，全绿**，覆盖 11 条路由。

## 1 · 做了什么

产品页从单页变成两层：`/products` 是入口，四个品类各有独立页面 `/products/:category`（`bra` / `bottoms` / `tops` / `outer`）。首页与产品页的品类四宫格都直接通向第二层。

每个品类页：品类页头（面包屑在页头内，替代原来的 eyebrow）→ **占位警示条** → 6 个款位 → 同级品类三宫格 → 询盘 CTA。

## 2 · 占位数据的处理原则

规格表**一个数值都没有填**。24 个款位（每品类 6 个）全部渲染成"待录入"，款号是 `WK-BR-01` 这类明显的槽位编号，页顶一条以 `--parent` 红为标识的警示条写明"请勿向客户报出其中任何一项"。

这是刻意的。SPEC 写了"无虚构数据"，而展会现场最现实的事故，是有人把编造的克重或 MOQ 念给客户听。看起来像真参数的假参数，比空白危险得多。

款位图也不用真实产品照，而是带斜纹的占位块——用平涂灰块会被当成图片加载失败，反而引人去查 bug 而不是去催产品清单。

录入方式写在 `src/data/site.js` 的 `placeholderSkus` 上方：把 `codes` 换成真实款号，给每条加一个按 `skuSpecFields` 的 id 组织的 `specs` 对象即可，组件会读到什么显示什么，缺的字段继续显示占位。

**断言 `A23` 会在数据录入后自动变红**——它检查"所有规格格子都还是待录入状态"，一旦有真实值填入而警示条还挂着，就会失败。这是提醒你撤警示条的机制。

## 3 · 本轮修掉的缺陷

**1 · 二级路由不点亮一级导航项。**
`/products/:category` 是 `/products` 的兄弟路由而不是子路由，所以 `router-link-active` 不会触发，站在品类页时导航栏没有任何高亮。改为路由在 `meta.navName` 里声明归属，`SiteNav` 据此判定。

**2 · `sizes` 提示与栅格脱节，图片被静默放大。**
`CardGrid4` 的 `sizes` 写死了四宫格的 `23vw`。加了 `columns` prop 之后，三宫格的实际格子是 428.7px，浏览器却按 331px 去取图，整行发虚且不报任何错。改为按列数计算：`(1350 − 32×(n−1)) / n`。

新增断言 `A24`（**任何图片的实际位图宽度不得小于它的渲染宽度**）之后，它立刻又抓出第二处：`MethodPair` 的容器 C 两栏实际是 `(1300 − 15) / 2 = 642.5px`，合 44.6vw，而代码里写的是 43vw，于是送了 619px 的图进 643px 的框。这是上一轮（Phase 2）留下的。

**3 · 面包屑会破坏 70px 节奏。**
面包屑最初是一个独立的 `.section`，夹在页头与下一区块之间。任何夹在两个 `.section` 中间的元素都会撑大被测量的间距，`A2` 会红。改为 `InnerHero` 的 `#top` 插槽——那里本来就是 eyebrow 的位置，而 eyebrow 干的正是"指出上级"这件事。

**4 · 面包屑与 h1 名称不一致。**
面包屑末项原本用 `nameKey`（"Sports Bras & Underwear"），h1 用 `titleKey`（"Sports Bras"），卡片上写的也是后者。三处统一为 `titleKey`；`nameKey` 保留给产品页面料段那行"品类覆盖范围"的完整名称。

**5 · 未定义的品类 slug 会渲染空页面。**
`beforeEnter` 现在把未知 slug 交给 404，而不是渲染一个什么都没有的页面。

## 4 · 数据结构上的整理

四个品类原本要写成两个数组（`categories` 给首页四宫格、`productCategories` 给二级页），是同一批东西的两份描述。已合并为 `categories` 一个来源，同时携带卡片图、页头图、路由目标与各级名称键。

## 5 · 素材

## 1 · 数据来源

## 2 · 有意没上站的两个字段

| 字段 | 为什么 |
|---|---|
| **库存**（逐 SKU 数量） | 每天在变，上线当天就是错的。而且是商业敏感数据。 |
| **条形码**（13 位 EAN） | 内部数据，对公开页面上的采购方没有任何用处。 |

断言 `A23` 里加了一条专门的检查：款式网格的文本中不得出现 13 位以上的数字串，也不得出现「库存 / stock」。

> 附带一提，这条检查第一次跑就红了——它匹配到的是**提示条里我自己写的那句解释**（"stock moves daily"）。检查范围已收窄到款式网格内。

## 3 · MOQ 与交期仍是唯一的空白

产品表里没有这两项（SPEC §11 Q8 早已记录）。卡片上它们显示为「面议 / On request」，页顶提示条从原来的「全部为占位」改成「两项仍待补」，并说明了库存为何不上站。

`A23` 现在断言**每款恰好 2 个待定格**：多了说明有字段被意外清空，少了说明数字到位了但提示条忘了撤。

## 5 · 图片

从 1.7GB 原始素材里选了 **24 个文件**入库（`03-图片素材/产品照片/`，压到管线可用尺寸后共 12MB）：

- **16 张单款去底图**，每款一张，配色挑有辨识度的而不是清一色黑
- **5 张棚拍**，用作品类页头与编辑位
- **3 张技术演示图**（五向支撑 / 石墨烯 / 弹力莱卡）

### 技术卡终于名实相符

站内 7 张技术卡里有 4 张原先用的是"最接近的一张照片"——**「石墨烯」配的是男款外套的领口特写**。新素材里这 3 张是专门为对应技术拍的，`tech-1 / tech-4 / tech-5` 已替换。另两张经像素比对确认，`单向导湿` 与 `TransThermal™` 就是素材库里已有的 `wandoak_p11_0` / `wandoak_p11_1`——也就是说 `tech-2` 一直是对的，只是此前没人知道那张图的确切含义。

### 去底图的归一化

16 张去底图的原始构图差异很大（衣服占画幅从约一半到几乎满幅），平铺出来像同一批货拍了五个不同距离。新增的 `mode: 'cutout'` 用 **alpha 通道**做归一化：`trim()` 削掉透明边距 → 按固定占比装进目标比例 → 合成底色。比 Phase 2 里给棚拍图用的亮度阈值法精确得多，因为 alpha 就是精确的物体边界。

底色默认取 `--wash-band`，可逐张覆盖；品类四宫格里那张外套用的是白底，因为它旁边三张是白底平铺图，灰底会露出自己的矩形。

## 6 · 本轮修掉的缺陷

**1 · 品类四宫格里的「外套」是一块看不出是什么的黑布。**
原先从 KNA 幻灯片的男款半拉链外套上裁了一块，缩到卡片尺寸后就是一个黑色矩形。现已换成产品线里真实的鸥蓝立领外套。

**2 · 品类页头裁到了脸上。**
四张新页头第一版按常规位置取，三张只拍到模特的脸，对一个要展示品类的页面毫无信息量。全部重新对准衣服。内衣页头又调了一次（0.24 → 0.30），落在领口、肩线与工字背上。

**3 · 单品类页面的栅格塌成半幅。**
外套只有 1 款，而 `SkuGrid` 原本在款数 ≤2 时切到两列，于是单张卡占了半个版面，看起来像布局坏了。改为恒三列。
